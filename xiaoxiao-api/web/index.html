01
WORKFLOW

五步，从一段录音到一份档案。

它不陪着聊天，它负责把这次会诊钉在纸上。 你只需要做一件事：按下「开始」。

  1. 01
    录音

    在手机上或电脑前按下「开始录音」，浏览器边听边转。音频不出这台设备，只留文字。 没有麦克风、或者当时忘了录，把问诊内容贴进输入框，一样能整理成记录。

  2. 02
    转写

    浏览器自带的语音识别实时落字，带时间戳。口语照原样留着，不改写、不润色； 它不区分说话人，药名剂量也可能听错 —— 关键的对着处方再核一遍。

  3. 03
    抽取

    从原文里抽出就诊时间、医院、诊断、过敏史、药品与剂量、饭前还是饭后、 疗程几天、哪天复诊、忌口什么。抽不到的字段留空，并当面告诉你哪几项没抽到。

  4. 04
    归档

    先给你看一遍，你点头才写入。一次就诊一条记录，连同原始转写一起存进这台设备， 关掉浏览器再打开，它还在。

  5. 05
    作答

    上一次是哪天、今天吃什么、饭前还是饭后、什么时候复诊 —— 它翻你的档案回答，每条都标出取自哪一次就诊；档案里没有，就说没有。

03
BOUNDARY

它不是医生，也装不成医生。

医疗场景里，最危险的不是答错，是答得像对的。所以它给自己立了三条硬规矩。

A

只答档案里有的

每条答案必须能翻到某一次就诊的某个字段。翻不到，它就回一句 「病历档案未查询到该内容，无法回答」，然后建议你复诊时问医生。

B

出处必须指到那次就诊

答案后面永远跟着来源：日期、医院、科室、档案号。 两次就诊说法不同时，它分开列出，不替你把它们揉成一个结论。

C

处方权在医生手里

它只复述你已经拿到的处方，不新增药、不改剂量、不判断该不该停药。 这类问题一律转成「下次复诊时问医生」。

每次回答的末尾

固定带一句：本内容仅为病历档案整理，不能替代医生诊疗意见。 页面里的患者、医院、处方都是构造的样例，只用于演示档案结构与检索方式。

04
ISOLATION

一个人一份档案，彼此看不见。

01
一人一个账号

资料与记录都存在 lx_records_v1_账号 这个键下， 各存各的。没登录进不来，登进来也只读得到自己那一份。

02
一个账号一条时间线

同一个账号可以存很多次就诊，按时间摞成一条线，全在「我的」里； 换个人登录，就是另一条干净的线。

03
别高估「本地」

转写用的是浏览器自带识别，音频可能被发送到浏览器厂商的云端——本页保证不了「声音不出设备」。 存下来的是文字：服务端模式下进你的账号，本机模式下在浏览器里。 不想要哪一条，在「我的」里点删除。

一句实话：
本机账号不是服务器鉴权。

登录只是把数据按账号分开存，密码也只在本机校验；它挡不住能打开这台电脑的人， 也挡不住清空浏览器数据 —— 清掉就没了。真要长期保存，得自己导出或接后端。
