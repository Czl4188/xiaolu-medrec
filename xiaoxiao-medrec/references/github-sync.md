# GitHub 同步（github-pat MCP，可选）

档案默认只在本机。启用 `github-pat` 后可以把病历 JSON 同步到**私有**仓库，实现换设备可读、可版本回溯。
这是拷贝，不是加密备份——仓库权限等于数据权限。

## 1. 前提

- 已启用 `github-pat` 连接器，token 具备 `repo` 权限（私有仓库读写）。
- 用户明确同意同步，并知道同步范围（哪几个 `patient_id`）。
- 仓库必须为 `private`。要同步到公开仓库时，必须二次确认并提示：

  > 公开仓库等同公开病历，任何人都能搜到。确认要继续吗？

## 2. 仓库结构（与本地同构，减少映射歧义）

```
medrec-archive/                 # 私有仓库
├── README.md                   # 写明"私人病历备份，请勿公开"
├── registry.json               # 仅 patient_id 与计数，不含临床内容
└── patients/
    └── pt_7f3a2c/
        ├── patient.json
        ├── index.json
        ├── visits/v_20260831_01.json
        └── transcripts/v_20260831_01.md
```

保持同构的好处：同步就是路径拼接 `仓库根 + 本地相对路径`，不需要额外映射表。

## 3. 同步时机

| 动作 | 行为 |
|---|---|
| 用户说"同步档案" | 增量：只推本地 `updated_at` 晚于仓库副本的文件 |
| 归档一份新病历后 | 不自动同步；询问"要同步到私有仓库吗" |
| 用户说"从仓库恢复" | 先列远端 `index.json`，确认后再拉取，**不覆盖**本地较新版本 |
| 用户说"删掉仓库里的" | 需二次确认；删除后提示本地仍保留 |

## 4. 提交信息规范

```
medrec: add v_20260903_01 (pt_7f3a2c)
medrec: update index for pt_7f3a2c
medrec: remove v_20260602_01 (pt_7f3a2c)
```

不带姓名、医院、诊断等临床信息，避免在提交历史里二次泄漏。

## 5. 冲突处理

1. 拉取前先比较 `updated_at`：
   - 远端更新 → 提示"仓库里这份比本地新，要以哪边为准？"
   - 本地更新 → 直接推。
   - 两边都改过 → 不自动合并；把两份都留下（本地 `*.remote.json`），让用户选。
2. 任何情况下不静默覆盖。覆盖前把被覆盖版本存为 `*.bak.json`。
3. 推送失败（权限、网络）→ 如实报错，本地档案不受影响，不重试到成功为止。

## 6. 读取路径

用户问"我上次看病是什么时候"时：

1. 先读本地 `index.json`；本地没有该 `patient_id` 才去仓库找。
2. 找到后**只读取该 patient_id 目录**，不列其他目录。
3. 远端读取的内容同样要标来源，格式不变：`【来源：2026-08-31 上海瑞金医院 消化内科 · v_20260831_01】`。

## 7. 关闭同步

用户说"别同步了"：

1. 立即停止后续推送；
2. 询问是否删除仓库里的副本；
3. 记录到 `registry.json` 的 `sync.enabled = false`，后续不再提示。
