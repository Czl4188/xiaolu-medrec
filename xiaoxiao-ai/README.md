# 小鹿 · 病历记录智能体（v3.1 复审整改版）

> 有后端时自动进入**服务端模式**（账号 / 档案 / 抽取 / 作答走 `/api`），没有后端则退回**本机模式**（localStorage）。
> 启动时探测同源 `/api/ping`（不用 `/healthz`，那个路径常被部署平台占用），顶栏会标出当前模式。
>
> **v3.1 针对《严格复审与整改建议》**：抽取未完成不得归档、日期/医院查询取交集、
> 过敏跨记录汇总、服务端故障不再用本机规则作答、引用可点击定位、资料真正同步服务端。

把一次问诊录下来，转成文字，整理成一页能翻回去的记录；看不懂药盒就拍一张。
之后的提问只在这些记录里找答案。

`app.html` 是完整应用：样式、脚本、五个视图全在一个文件里，双击即用，不依赖任何外部资源。

## 页面

单页切换，不跳转新 HTML：

| 视图 | 作用 |
|---|---|
| 登录闸 | 用户名 + 密码；未登录看不到任何页面 |
| 首页 | 你的信息、巨大的「开始」、「我的」、「拍照识药」 |
| 拍照识药 | 拍药盒 / 处方 → 千问识图 → 可编辑卡片 → 加入本次病历用药 |
| 我的 | 头像、资料（含身份证）、就诊记录与完整转写 |
| 工作台 | 录音 / 手动整理 / 对话 / 今日用药 |

顶部导航：首页 · 识药 · 我的。识药页左上还有「← 返回首页」。

## 一次完整使用

1. **登录**：用户名 + 密码。首次使用先勾选「创建新账号」；已有账号直接登录，输错用户名不会偷偷建号。
2. **首页**：头像、姓名、年龄性别、身份证尾号、记录数；点「开始」进工作台并请求麦克风。
3. **录音**：右上「开始录音」，浏览器边听边转，逐段落下带时间戳的原文。
   说完点「停止录音」→ 抽字段 → 弹窗里可逐项修改 → 确认才归档。
4. **拍照识药**：首页第二行「拍照识药」→ 拍照或从相册选 → 识别结果以卡片呈现，
   药名 / 剂量 / 频次 / 饭前饭后都能改 →「添加到本次病历用药」。
5. **提问**：`我上次看病是什么时候` / `我今天要吃什么药` / `什么时候复诊` / `我一共看过几次`。
   医疗类回答都带 `依据：日期 · 医院 · 第 N 次` 和固定声明「不构成诊疗建议」。
6. **看旧记录**：首页「我的」——左侧改资料，右侧按时间排的就诊记录；点一条展开完整转写。
7. **换主题**：顶栏右侧下拉，暖纸 / 暗夜 / 浅白，立即生效，按账号记住。
8. **改旧记录**：在「我的」展开任意一条，点「修改」可改日期、医院、诊断、用药、复诊、过敏、注意事项；
   原始转写不动，服务端模式下用 `PATCH /api/records/{id}` 落库。

没有麦克风时：工作台左栏有输入框，把问诊内容贴进去点「整理成记录」，走同一条抽取与归档路径。

## 数据存在哪

浏览器 `localStorage`，按登录账号分键，互不可见：

```
lx_accounts_v1            账号列表（用户名 + 密码散列）   ← 仅本机校验
lx_session_v1             当前登录的账号
lx_user_v1_<账号>         { name, age, gender, hospital, avatar, idcard }
lx_records_v1_<账号>      [ { id, at, hospital, summary, transcript, meds, ... } ]
lx_theme_v1_<账号>        主题：warm / dark / light
lx_ai_v1_<账号>           { base, key, textModel, visionModel }
lx_scan_v1_<账号>         [ { id, at, meds, thumb } ]  最多 20 条
lx_theme_guest_v1         登录前用的主题（避免刷新闪白）
```

- 头像：从相册选图，前端裁成 256×256 JPEG（base64）存进 `profile.avatar`；首页、顶栏、我的三处同步换。
- 身份证：存进 `profile.idcard`，页面上只显示 `••••1234`；提示写明「仅保存在本机浏览器，不会上传任何网络」。
- 每次归档、改资料、删记录、换主题、识药成功都立刻落盘。
- 记录里的 `at` 是真实 `Date.now()`，页面时钟每秒读系统时间——没有写死的演示日期。
- 密码只做本机校验（前端散列），**不是服务器鉴权**；清空浏览器数据即全部丢失。

> 头像与身份证**只写 localStorage**，即使处于服务端模式也不会随 `/api/me/profile` 上传。

## 语音

| 能力 | 实现 | 不可用时 |
|---|---|---|
| 转写 | `SpeechRecognition` / `webkitSpeechRecognition`，`zh-CN`，连续识别 | 录音键禁用，给提示，改用手动输入 |
| 朗读 | `speechSynthesis`，逐段读，**默认关闭**（公共场所外放病情是真实风险） | 顶栏按钮禁用，只显示文字 |

- 顶栏右侧：喇叭按钮切换「朗读 / 静音」，旁边滑块调音量（0–100，内存态，不持久化）。
- 音量归音量，开关归开关：拖动滑块不会偷偷把朗读打开。
- 兼容性提示写在工作台左栏顶部，不弹窗、不报错。

## 拍照识药（千问）

前端只做**选图、压缩、预览**，不引第三方 OCR。识图交给千问 VL（DashScope 的 OpenAI 兼容接口）：

```
POST {base}/chat/completions
model: qwen3-vl-plus
messages: [ { role:user, content:[ {type:text}, {type:image_url, image_url:{url:data:image/jpeg;base64,...}} ] } ]
```

- 在识药页点「千问设置」填 **接口地址 / API Key / 文本模型 / 识图模型**，有「测试连接」。
  默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`、`qwen-plus`、`qwen3-vl-plus`。
- 未填 Key：**不编造识别结果**，明确提示本机没有 OCR，并给一张可手填的卡片。
- 识别结果全部可改；卡片上的「添加到本次病历用药」会走三条路：
  1. 有未归档草稿 → 加进草稿，回工作台确认归档；
  2. 有历史记录 → 确认后加进**最近一次**就诊，并在服务端模式下 PATCH 同步；
  3. 一份记录都没有 → 建一份草稿，提醒补医院与诊断。
- 同名药不重复添加（避免把两条不同剂量的记录混在一起）。
- Key 存在本账号的 localStorage；识别请求从浏览器直发千问。

**两个现实约束**

1. 千问接口未开放浏览器跨域时，直连会被 CORS 拦下——需要走支持 CORS 的网关或本机代理，
   失败时页面会把原因显示出来，不会假装成功。
2. 识图会看错，剂量尤其容易错。卡片是「待核对」的草稿，不是处方。

## 对话与千问

`send()` 的顺序是：服务端模式 → 用服务端结论；否则先跑本机规则，再决定要不要请千问组织语言。

- **有依据**（命中某次记录）→ 把「档案摘要 + 本机检索结论」一起给千问，只让它换说法，不让它加事实；
- **普通闲聊**（自我介绍、你能做什么）→ 用另一套提示词，60 字以内；
- **拒答 / 急症 / 求诊疗建议** → 千问不参与，直接走本机安全话术；
- 模型若给出「可以吃 / 停药 / 加量」这类越界句子，而本机结论里没有 → **整条丢弃，回退本机文案**。

所以答案里的日期、药名、来源仍然来自档案；千问只负责说得像人话。

## Agent 的回答规则

**会答**（只从记录里取，取不到就说取不到）

- 上次什么时候、一共几次、某家医院某天那次
- 上次开了哪些药、剂量、饭前饭后、吃几天
- 复诊时间、过敏史、注意事项
- 档案里记过的疾病 / 事件（胃镜、高血压、手术……）

**会拒答**

`能不能吃…` `要不要停药` `严重吗` `怎么治` `我今天吃药了吗` —— 统一说「查不到 / 无法确认」，不编医嘱。

**急症**

`胸痛` `呼吸困难` `大出血` 等 → 直接给 120 / 急诊提示，**不引用档案、不给用药建议**。

**会闲聊**

`你叫什么名字` `你能做什么` `几点了` `谢谢` —— 正常应答，不硬拗成病历问题。

## 本轮复审整改（按报告逐项）

| 编号 | 处理 |
|---|---|
| **P0-01** 抽取竞态 | 草稿有 `extracting / ready / failed` 状态；整理期间保存按钮禁用、左栏也标「整理中」。响应绑定草稿 ID + 请求序号，旧响应不覆盖新草稿；用户改过的字段**逐字段保留**，服务端只补没改的部分。抽取失败切全手工，不再用本机规则猜。 |
| **P0-02** 日期/医院查错 | 先把问题解析成 `{日期, 医院, 第几次}`，多个条件取交集；没有匹配就明确说「没有找到符合条件的记录」，**不拿最近一次顶替**。日期支持 `2026-10-01 / 2026年10月1日 / 10月1日`，医院支持简称匹配。 |
| **P0-03** 过敏被覆盖 | 「最近一次医嘱用药」和「档案概览」改为**跨记录汇总**：阳性记录优先，其次「否认」，最后才是「所有记录均未记录（不等于没有）」，并标出日期。 |
| **P0-04** 降级风险 | 服务端模式下，抽取失败 → 全手工；对话失败 → 明确说「这条没有作答」，**不再用本机旧规则生成药单**。 |
| **P1-01** 空白引用 | `citations` 统一为对象 `{label, recId}`；来源标签显示日期 / 医院 / 第几次，可点击跳到「我的」并展开对应记录。 |
| **P1-02** 资料不同步 | 服务端模式下保存资料调用 `PUT /api/me/profile`，成功才提示「已同步」，失败明确说「只存到本机」。头像与身份证仍只存本机（按需求）。 |
| **P1-03** 日期污染医院 | 医院抽取前先剥离日期/时段；后端 `visit_hint`、前端 `guessVisitDate` 从原文识别就诊日期，弹窗提示「年份请确认」。 |
| **P1-04** 漏药 / 不能加药 | 内置常用药名词典（阿莫西林、胰岛素等不带剂型也能认）；归档弹窗支持 **添加药物 / 删除药物**，空行保存时自动过滤。 |
| **P1-05** 归档后不能改 | 记录详情新增「修改」，同一弹窗改完 PATCH；详情补齐疾病/事件、停用药、否认过敏。 |
| **P1-06** 假打卡 | 改名为「最近一次医嘱用药」，移除服药勾选；最近一次没开药时，展示「上一次有用药」的医嘱并标注日期。 |
| **P1-07** 文案矛盾 | 登录页底部、工作台空态、概览角标按「服务端 / 本机」动态显示；删除「识别只在本机进行」这类不实说法。 |
| **P1-08** 录音与账号 | 首页「开始」只进工作台，不自动开麦；左栏常驻「征得医生与在场人同意」提示。登录拆分「登录 / 创建新账号」。密码找回与账号注销尚未做。 |
| **P1-09** 接口暴露 | `/api/ping` 只返回 `{status, app}`；新增 CSP、Permissions-Policy、`X-Frame-Options: DENY`、`/api/*` `no-store`。 |
| **P2-01** 手机弹窗 | 药物行改为独立卡片：桌面五列、手机两列，删除按钮独立；保存按钮固定在弹窗底部。 |
| **P2-04** 长原文塞输入框 | 不再自动填入聊天框；草稿卡新增「用这段问小鹿」，需要时才带入。 |
| **P2-05** 保存与导出 | 顶栏显示「保存中 / 已保存 / 保存失败」；保存中禁用导出；服务端模式导出前重新拉最新档案。 |

**仍未做**：P2-02 手机工作台标签页重排、P2-03 底部导航与整体字号放大、P2-06 可打印/PDF 版本；
修改密码、找回密码、注销账号与服务端彻底删除。这些不影响本轮 P0/P1 的结论，但上线真实用户前仍需补。

## 已知限制

- **只在 Chrome / Edge 上完整**：Safari 与 Firefox 的语音识别支持不完整，会降级成手动输入。
- **`file://` 下识别可能被拦**：必要时用本地服务器打开（`python -m http.server`，访问 `http://localhost:8000/app.html`）。
- **识别不区分说话人**：转写是一整段，不标注「医生 / 患者」；药名剂量会听错，关键项对处方核。
- **抽取是规则不是模型**：正则覆盖常见说法（「每天两次」「饭后」「吃14天」「两周后复诊」），
  生僻表述会抽空——空着比编造好，界面上会写明「未抽到」。
- **不是医疗器械**：不诊断、不开药、不判断轻重。
- **本机模式仍用规则抽取**：服务端模式已改为「服务端抽取 / 失败即手工」；纯本机模式使用同一套规则（多药独立绑定、否定句、日期识别），但仍需逐项核对。
- **账号生命周期不完整**：目前只能登录 / 创建，没有改密、找回、注销。

## 设计

处方笺档案（Editorial archive）：暖纸白 `#f2ece0`、黑体标题、宋体正文、等宽数字、
楷体页边批注，全站一个印泥红。不用渐变、不用玻璃拟态、不用三张等高卡片。

三套主题只换「纸、墨、印」，版式、字阶、栅格一律不动：

| 主题 | 纸 | 强调 | 正文 |
|---|---|---|---|
| 暖纸 | `#f2ece0` | 印泥红 `#a6341f` | 宋体 |
| 暗夜 | `#141310` | 陶红 `#d97862` | 宋体 / 深底反相 |
| 浅白 | `#f5f7f6` | 医用青 `#0f6e63` | 宋体 / 近白 |

首页只有三件东西：你是谁、一个巨大的「开始」、两个去处。
